# Architecture

```
┌──────────────── Browser (user's own profile) ────────────────┐
│ Puddock extension (MV3)                                       │
│  background ─ toolbar / Alt+M / context menu / options page   │
│  content    ─ ▶ button on channel pages                       │
│  chat       ─ popout chat: become a popup window, mark it     │
└───────────────┬──────────────────────────────────────────────┘
                │ Native Messaging (stdio, JSON, com.puddock.native)
┌───────────────▼──────────────────────────────────────────────┐
│ puddock.exe (AutoHotkey v2, compiled)                          │
│  host mode   ─ short-lived, started by the browser per message │
│  player      ─ one window: mpv + divider + embedded chat       │
│  launcher    ─ channels, settings, account, setup              │
└───────┬───────────────────────────────┬───────────────────────┘
        │ starts directly (no shell)    │ re-parents
   streamlink ──► mpv (--wid)       browser popout-chat window
```

## Components

- **Launcher** (`puddock.exe`, `--setup`, `--settings`): favourites/recent channels, settings, Twitch account, dependency detection (PATH, registry, well-known folders) and optional winget installs.
- **Player** (`puddock.exe <channel>` / `--watch`): single instance. Starts `streamlink --player <full path to mpv> --player-args "--wid=<hwnd> …" twitch.tv/<channel> <quality>` with `CreateProcess` (no shell), its stdout/stderr redirected into `%TEMP%\puddock-<channel>.log`; embeds mpv's window, embeds the chat window, provides menu/tray/toolbar/hotkeys.
- **Native host** (same exe, detected from argv: Chromium passes `chrome-extension://<id>/`, Firefox passes the manifest path and the extension ID). Reads length-prefixed JSON from stdin, answers on stdout, exits when stdin closes. Usually one message per process; for an embedded chat the extension keeps a port open (`attach`, see *Chat commands*).
- **Sources**: `app/puddock.ahk` holds the constants, the entry point and the hotkeys; everything else is classes and functions in `app/lib/*.ahk` (`Player`, `Launcher`, `TopBar`, `Widgets`, `Config`, `Process`, `Tools`, `Chat`, `Host`, `App`, `Account`, `Ui`, `Json`). `tests/run.ahk` includes the same files and tests the pure functions.
- **Extension**: Chromium MV3 source in `extension/`; the Firefox package is generated by `build/build.ps1` (background scripts instead of a service worker, gecko id `puddock@puddock.app`).

## Flows

### Watch from the browser
1. User clicks the toolbar button / Alt+M / context menu on a Twitch channel.
2. Extension → host: `{"cmd":"watch","channel":"xqc","nonce":"<random hex>"}`.
3. Host validates the channel (and that streamlink + mpv are present — otherwise it opens Setup and says so), starts `puddock.exe --watch xqc --chat-nonce <nonce>` (detached) and replies `{"ok":1,"chat":1,"chatDark":1}`. If that channel is already playing it only brings it to the front and replies `"chat":0`.
4. Extension opens the popout chat itself — `…/popout/xqc/chat?puddock=<nonce>` as a `type: "popup"` window — so it lands in the browser that has the extension, then the handshake below continues from step 2. (The app remembers the last few chat nonces for 10 minutes each, so quick repeated requests don't invalidate one another.)
5. Player: if another channel is playing it closes that player first.

### Chat embedding handshake
1. Started from the launcher (no nonce yet), the player opens `https://www.twitch.tv/popout/<channel>/chat?puddock=<nonce>` in the user's default browser if the extension has been seen there recently.
2. Extension content script (popout pages) sees `puddock=<nonce>`, asks the background to move the tab into a `type: "popup"` window, and sets the document title to a marker containing the nonce and the browser-chrome insets (CSS px × devicePixelRatio).
3. Player finds the top-level window whose title contains the nonce, removes its frame styles, re-parents it into the chat panel, and offsets it by the insets so only the page is visible (Chromium: insets measured from the `Chrome_RenderWidgetHostHWND` child; Firefox: from the marker).
4. Without the extension (or if no marked window shows up within 15 s), the player falls back to a Chromium browser in `--app` mode: the configured fallback browser, else the default browser if it is Chromium-based, else Brave / Chrome / Edge / Vivaldi / Opera.

### Chat commands (settings, zoom, reload)
1. When the background confirms a chat nonce (`chat-ready`), it opens a native-messaging port (`connectNative`) and sends `{"cmd":"attach","nonce":"…"}`. The browser keeps that helper process running while the port is open; the helper names its hidden window `puddock-port-<nonce>`.
2. The player (menu, toolbar, F5 / F10) finds that window and sends it one word with `WM_COPYDATA`; the helper checks it against a fixed list and writes `{"type":"chat","action":"…"}` to the port; the background forwards it to the chat tab; `chat.js` does it.
3. No port (older extension, port closed): the player gives the chat the keyboard focus and types the page's own shortcut instead (Alt+Shift+S / Up / Down / 0 / R, handled by `chat.js`).
4. The port closes with the chat tab; the helper also ends by itself when no player has been running for a minute.

### Input and timers
- Clicks on the video and on the chat (windows of other processes) are noticed through raw input (`WM_INPUT`), not a mouse hook.
- The player's timer runs every 100 ms while the stream starts and every 300 ms once the video plays; the toolbar's hover timer runs only while the player is the foreground window.

### Settings sync
- Single source of truth: `%APPDATA%\Puddock\settings.ini`.
- Extension options page → `getSettings` / `setSettings` (whitelisted keys, validated, written by the host). The launcher reads the same file; a running player picks changes up on the next stream (re)load.

### Connect Twitch account
1. Options page → *Connect Twitch account* → `permissions.request({permissions:["cookies"]})`. (The launcher's *Connect in browser* button opens `https://www.twitch.tv/?puddock=connect-<nonce>`; the extension asks the app `checkNonce` and only then opens its options page — a web page can't fake that link.)
2. Extension reads the `auth-token` cookie of `https://www.twitch.tv` and sends `{"cmd":"setToken","token":"…"}`.
3. The extension gives the cookie permission back immediately (`permissions.remove`).
4. Host validates it at `https://id.twitch.tv/oauth2/validate` (must belong to twitch.tv's own web client), stores it in Windows Credential Manager, replies with the login name. `clearToken` removes it.
5. When a stream starts, the player creates the named pipe `\\.\pipe\puddock-<random>` (current user only, no remote clients, first instance) and starts streamlink — suspended, inside a kill-on-close job object — with the argument `@\\.\pipe\puddock-<random>`. streamlink's argparse reads arguments from that "file"; each time a client connects, the player checks with `IsProcessInJob` that it belongs to streamlink's job, writes `twitch-api-header=Authorization=OAuth …` and closes that instance once it has been read — 2 s later at most; the wait (`FlushFileBuffers`) runs on a helper thread, so a client that never reads cannot hang the player — (a clean EOF for Python; closing rather than `DisconnectNamedPipe`, which would raise an error in the reader) while a fresh instance keeps the name answering — argparse reads it again once the Twitch plugin is loaded. Once streamlink logs the stream list (or after 30 s) the pipe is closed for good. streamlink's own config files keep working, since no `--config` is used.

## Native host registration (`puddock.exe --install`)

Writes manifests to `%APPDATA%\Puddock\native-host\`:
- Chromium-family manifest: `{"name":"com.puddock.native","type":"stdio","path":"<puddock.exe>","allowed_origins":["chrome-extension://<id>/", …]}`
- Firefox manifest: same, with `"allowed_extensions":["puddock@puddock.app"]`.

And points these per-user registry keys (default value = manifest path) at them:

| Browser | Key |
| --- | --- |
| Chrome | `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.puddock.native` |
| Chromium | `HKCU\Software\Chromium\NativeMessagingHosts\com.puddock.native` |
| Edge | `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.puddock.native` |
| Brave | `HKCU\Software\BraveSoftware\Brave-Browser\NativeMessagingHosts\com.puddock.native` |
| Vivaldi | `HKCU\Software\Vivaldi\NativeMessagingHosts\com.puddock.native` |
| Firefox | `HKCU\Software\Mozilla\NativeMessagingHosts\com.puddock.native` |

`--uninstall` removes the keys, our manifest files and the saved token (settings are kept).

Allowed extension IDs are constants at the top of `app/puddock.ahk` (`CHROMIUM_IDS`, `GECKO_ID`). Puddock is distributed on GitHub only, so the trusted Chromium ID is the one fixed by the public `key` in `extension/manifest.json`; add store IDs there if the extension is ever listed.
